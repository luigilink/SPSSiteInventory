# Alerts and remediation

SPSSiteInventory turns the signals it collects into **alerts**. An alert says that a site
collection, a web application or the farm has something to deal with before or after the
migration, how serious it is, and what to do about it. Alerts are about risks found by the
inventory; they are not the SharePoint alerts (Alert Me subscriptions) that users configured.
Those are inventoried in their own `*-sharepointalerts-*` files (see
[Usage](Usage#sharepoint-alerts)) and raise a single `Medium` alert per site collection.

## Where to find them

- The **Alerts and remediation** section of the HTML report groups the alerts by type, most
  severe first, with the number of site collections or web applications concerned. Each type is
  a line that opens to show what it means, what to do about it and the Microsoft Learn page.
  The **Risk indicators** above it rank the signals by the share of site collections that raise
  them, grouped by the severity of the alert of each signal.
- `*-alerts-*.csv` (for Excel) and `*-alerts-*.json` list every alert with the URL it is
  about. The files are described in [Usage](Usage#output-files).

Each alert has these fields:

| Field | Description |
| --- | --- |
| `AlertType` | The kind of alert, from the table below. |
| `Severity` | `High` for a finding that blocks or breaks a migration (or the modern experience, in the [`SharePointOnPrem` mode](#alerts-in-the-sharepointonprem-mode)), `Medium` for one that needs a plan or a check, `Low` for information to pass on. |
| `Url` | The site collection or web application the alert is about. Empty for farm-wide alerts. |
| `Value` | What raised the alert: a count, a state, a template or a LOB system name. |
| `Message` | What was detected and why it matters. For the template alerts it is the reason of the mapping. |
| `Remediation` | What to do next. The same alert type always gives the same advice. |
| `Reference` | The Microsoft Learn page behind the advice, when there is one. |

The advice comes from the guidance of the SharePoint Migration Assessment Tool (SMAT) scan
reports and the Microsoft documentation. Where a SMAT page predates a retirement, as for
workflows, add-ins and SharePoint alerts, the advice follows the current Microsoft
documentation instead. It is a starting point: confirm it against your own target and plan.

## Alerts in the SharePointOnPrem mode

The alert types are the same in both [target modes](Configuration#targetmode-section), in the same
order, but the catalog of the `SharePointOnPrem` mode answers the other question: what stands
between a site collection and the modern experience on the farm where it runs. The alerts files and
the HTML report use the catalog of the mode of the run.

**Alerts that are only about a migration to SharePoint Online are `Low`** in this mode, and say so:
the message starts with "Migration to SharePoint Online only." and the remediation with "Nothing to
do to modernize this farm. If you migrate to SharePoint Online, this applies.", followed by the text
of the table above, so nothing is lost for whoever migrates later. They are `CustomPermissionLevels`, `EmailEnabledLists`, `HtmlFiles`, `ManagedMetadataColumns`, `ExternalLists`, `AlertSubscriptions`, `UnsupportedSiteTemplate`, `TemplateCompatibilityReview`, `TemplateLanguageReview`, `FbaConfigured`, `IrmEnabledLists`, `LargeSite`, `CheckedOutFiles`, `FileVersions`, `LargeExcelFiles`, `WebApplicationPolicies`, `PermissiveBrowserFileHandling`, `BcsApplication`, `SecureStoreApplication`, `AudienceTargeting`, `SiteNotebook`, `ProfilePropertyMapping`, `CustomizedProfilePage`.

**`ModernExperienceOptOut`** is `Medium` instead of `Low`, with the same text: the opt-out is what
keeps the lists of a site collection or a web in the classic experience. The other alerts about the
modern experience (`AlternateCssUrl`, `XsltListViews`, `ScriptWebParts` and `ClassicExperienceLists`)
and the alerts that say that the inventory itself is incomplete (`WebApplicationEnumerationFailed`,
`AssessmentFailed`, `BcsInventoryPartial`, `SecureStoreInventoryPartial`, `ProfilePropertyMappingInventoryPartial`) are the same in both modes.

Inventory the forms with their owners, rebuild them and test the replacements during user acceptance testing. | `NoAccessSite` | Medium | The site collection is locked with NoAccess: it cannot be read, so the inventory cannot assess it. | Check that the lock is intended. | `LockedSite` | Low | The site collection is locked NoAdditions or ReadOnly: its content can still be read, but adding or changing content is restricted. | Check that the lock is intended. A NoAdditions lock prevents adding content and a ReadOnly lock prevents adding, updating and deleting it, so the modernization of the site needs it unlocked: change the lock only when the work starts. | `Subsites` | Low | This site collection has subsites.
